# 📬 MailPanel — پنل ایمیل روی دامنه اختصاصی شما

پنل ایمیل کامل و حرفه‌ای بر بستر **Cloudflare Workers + Email Routing + KV** — بدون سرور، بدون هزینه (پلن رایگان کلادفلر کافی است).

| امکانات |
|---|
| ✉️ ساخت بی‌نهایت آدرس ایمیل روی دامنه خودت (`info@domain.com`، `support@domain.com` و…) |
| 🔐 هر صندوق رمز ورود مستقل + پنل مدیریت با رمز ادمین |
| 🌐 پنل دوزبانه (فارسی راست‌چین پیش‌فرض + سوییچ انگلیسی) با طراحی تیره پریمیوم |
| 📎 نمایش ایمیل‌های HTML در قاب ایزوله (ضد اسکریپت مخرب) + دانلود پیوست |
| ⭐ خوانده/نخوانده، ستاره‌دار، حذف، جستجو در فرستنده و موضوع |
| ↩️ پاسخ به ایمیل‌ها از داخل پنل (با Resend — اختیاری) |
| 📱 کاملاً ریسپانسیو برای موبایل |

## 🚀 نصب با داشبورد کلادفلر (بدون ترمینال) — ۱۰ دقیقه

> پیش‌نیاز: دامنه‌ات روی Cloudflare فعال باشد (پلن رایگان هم کافی است).

### مرحله ۱ — ساخت Worker

1. وارد [dash.cloudflare.com](https://dash.cloudflare.com) شو.
2. از منوی چپ: **Workers & Pages** → دکمه **Create** → تب **Create Worker**.
3. یک نام بده مثلاً `email-panel` → دکمه **Deploy** (فعلاً کد پیش‌فرض مهم نیست).
4. بعد از دیپلو روی **Edit code** کلیک کن.
5. کل کد داخل فایل `worker.js` را انتخاب و پاک کن (Ctrl+A سپس Delete) و **محتوای کامل `worker.js` این پکیج را پیست کن**.
6. دکمه **Deploy** (بالای ادیتور) را بزن → پیام موفقیت ببینی.

> ⚠️ فایل حدود ۲۰۰ کیلوبایت است؛ چند لحظه زمان می‌برد. اگر ادیتور کند شد، جایگزینی کامل متن را با یک Paste انجام بده نه تکه‌تکه.

### مرحله ۲ — ساخت دیتابیس KV

1. از منوی چپ داشبورد: **Storage & Databases** → **KV**.
2. **Create namespace** → نام: `email-panel-kv` → Create.

### مرحله ۳ — اتصال KV به Worker (Binding)

1. برو به **Workers & Pages** → روی `email-panel` کلیک کن.
2. تب **Settings** → بخش **Bindings** → **Add binding**.
3. نوع: **KV Namespace**.
4. **Variable name:** دقیقاً بنویس `MAIL_KV` (حروف بزرگ با زیرخط).
5. **KV namespace:** همان `email-panel-kv` که ساختی → **Deploy/Save**.

### مرحله ۴ — متغیرها و رمزها

در همان **Settings**:

**۴-الف) متغیر دامنه** — بخش **Variables** (یا Variables and Secrets):
- **Add** → Type: `Text` → Name: `DOMAIN` → Value: دامنه خودت مثل `example.com` (بدون `https://` و بدون `www`)

**۴-ب) رمز ادمین** — همان‌جا:
- **Add** → Type: `Secret` → Name: `ADMIN_PASSWORD` → Value: یک رمز قوی (حداقل ۶ کاراکتر)

**۴-ج) کلید امضای نشست‌ها (پیشنهادی):**
- **Add** → Type: `Secret` → Name: `SESSION_SECRET` → Value: یک رشته تصادفی طولانی (مثلاً از random.org یا هر متن بی‌معنی ۳۰ کاراکتری)

> 💡 اگر `ADMIN_PASSWORD` تنظیم نکنی هم اشکالی ندارد: بار اول که پنل را باز کنی، صفحه «راه‌اندازی اولیه» رمز ادمین را می‌پرسد و هش‌شده در KV ذخیره می‌شود.

**۴-د) اختیاری — رد کردن ایمیل‌های ناشناس:**
- Type: `Text` → Name: `REJECT_UNKNOWN` → Value: `true`
- پیش‌فرض (خالی): ایمیل به آدرس‌های تعریف‌نشده بی‌صدا حذف می‌شود؛ با `true` فرستنده پیام «ناشناس بودن آدرس» می‌گیرد.

### مرحله ۵ — فعال‌سازی Email Routing (مهم‌ترین مرحله!)

1. از داشبورد اصلی، دامنه‌ات را انتخاب کن.
2. منوی چپ: **Email** → **Email Routing**.
3. اگر پیام فعال‌سازی آمد: **Enable Email Routing** (کلادفلر خودش رکوردهای MX و SPF را اضافه می‌کند؛ چند لحظه صبر کن).
4. تب **Routing rules** → پایین صفحه بخش **Catch-all address** → **Edit**.
5. تنظیم کن:
   - Action: **Send to a Worker**
   - Destination: `email-panel` (ورکر خودت)
6. **Save**.

از این لحظه **هر ایمیلی به هر آدرسی روی دامنه‌ات** به ورکر می‌رسد؛ ورکر فقط ایمیل‌های صندوق‌های ساخته‌شده را ذخیره می‌کند و بقیه را حذف/رد می‌کند.

### مرحله ۶ — ورود به پنل و ساخت اولین صندوق

1. آدرس ورکر را باز کن: `https://email-panel.<نام-اکانت>.workers.dev`
2. اگر `ADMIN_PASSWORD` تنظیم کرده‌ای → از پایین صفحه **ورود مدیر**؛ وگرنه صفحه راه‌اندازی اولیه، رمز ادمین را می‌سازد.
3. در پنل مدیریت: آدرس صندوق (مثل `info@example.com`) و رمز آن را وارد کن → **ساخت صندوق**.
4. حالا از هر جای دنیا به `info@example.com` ایمیل بفرست؛ طی چند ثانیه در پنل ظاهر می‌شود. ✅

### مرحله ۷ — تست

- به آدرس صندوق ایمیل بزن (مثلاً از جیمیلت) → در پنل، وارد صندوق شو با همان ایمیل و رمزش.
- ایمیل باید در «ورودی» باشد؛ با کلیک، متن/HTML و پیوست‌ها را ببین.

## ↩️ فعال‌کردن دکمه پاسخ (اختیاری — با Resend)

دکمه پاسخ به‌صورت پیش‌فرض خاموش است؛ برای روشن کردنش یک کلید API رایگان از Resend لازم است:

1. ثبت‌نام در [resend.com](https://resend.com) (رایگان: ۳۰۰۰ ایمیل در ماه).
2. از پنل Resend: **API Keys** → **Create API Key** → کلید را کپی کن.
3. **Domains** → **Add Domain** → دامنه‌ات را وارد کن → Resend چند رکورد DNS (DKIM و…) می‌دهد؛ چون دامنه‌ات روی Cloudflare است، همان‌جا در بخش DNS اضافه‌شان کن و در Resend **Verify** بزن.
4. برگرد به Cloudflare → Worker → Settings → Variables:
   - **Add** → Type: `Secret` → Name: `RESEND_API_KEY` → Value: کلید کپی‌شده
5. حالا در صندوق هر ایمیل، دکمه **پاسخ** فعال است و پاسخ‌ها در تب «ارسال‌شده» ذخیره می‌شوند.

> ⚠️ بدون تأیید دامنه در Resend، ارسال از دامنه خودت کار نمی‌کند (این محدودیت Resend است نه پنل).

## 🛠 دیپلوی اختیاری با Wrangler (ترمینال)

اگر بعداً خواستی با ترمینال کار کنی:

```bash
npm install
npx wrangler login
# ۱) ساخت KV و قرار دادن id آن در wrangler.toml
npx wrangler kv namespace create MAIL_KV
# ۲) دامنه را در wrangler.toml ویرایش کن
# ۳) سکرت‌ها:
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET
npx wrangler secret put RESEND_API_KEY   # اختیاری
# ۴) دیپلو:
npx wrangler deploy
# ۵) قانون Catch-all → Worker را یک‌بار مثل مرحله ۵ در داشبورد بزن
```

| مشکل | راه‌حل |
|---|---|
| ایمیل به صندوق نمی‌رسد | ۱) رکوردهای MX دامنه را چک کن (Email → Settings → باید MXهای کلادفلر فعال باشند). ۲) مطمئن شو Catch-all → Worker ست شده. ۳) صندوق با **آدرس دقیق** و حالت **فعال** ساخته شده باشد. |
| خطای «MAIL_KV binding missing» | مرحله ۳ را دقیق تکرار کن؛ نام متغیر باید دقیقاً `MAIL_KV` باشد. |
| بعد از تغییر `ADMIN_PASSWORD` لاگ‌ات شدی | طبیعی است — نشست‌ها با رمز ادمین امضا می‌شوند؛ دوباره وارد شو. |
| دکمه پاسخ نیست / خطای NO_KEY | `RESEND_API_KEY` تنظیم نشده یا دامنه در Resend تأیید نشده (بخش پاسخ را ببین). |
| پیوست دانلود نمی‌شود | پیوست‌های بزرگ‌تر از ۱۰ مگابایت ذخیره نمی‌شوند (فقط نامشان می‌آید). |
| فونت‌ها لود نمی‌شوند | فونت از jsDelivr می‌آید؛ اگر در شبکه‌ات فیلتر است، پنل با فونت جایگزین (Tahoma/Segoe UI) همچنان کامل کار می‌کند. |

## 🔒 نکات امنیتی و محدودیت‌ها

- رمزها با **PBKDF2-SHA256** (۵۰هزار دور) هش می‌شوند و هیچ‌وقت خام ذخیره نمی‌شوند.
- نشست‌ها کوکی **HttpOnly + Secure** با امضای HMAC-SHA256 هستند؛ ۷ روز اعتبار دارند.
- ایمیل‌های HTML در `<iframe sandbox>` بدون اجازه اسکریپت رندر می‌شوند — اسکریپت مخرب اجرا نمی‌شود؛ پیوست‌ها هم با `Content-Disposition: attachment` و MIME عمومی دانلود می‌شوند.
- محدودیت پلن رایگان KV: حدود **۱۰۰۰ نوشته در روز** — برای دریافت ایمیل شخصی کاملاً کافی است؛ اگر ایمیل خیلی زیاد داری، پلن $5 ماهانه Workers را بگیر.
- حداکثر حجم هر ایمیل ورودی طبق محدودیت خود کلادفلر **۲۵ مگابایت** است (پیوست‌های بزرگ‌تر از ۱۰MB در پنل ذخیره نمی‌شوند).
- جستجو روی ۳۰۰ پیام اخیر (فرستنده + موضوع) اعمال می‌شود.
- سرویس «پاسخ» به Resend وابسته است؛ اگر کلید را حذف کنی فقط دکمه پاسخ خاموش می‌شود و بقیه پنل سالم می‌ماند.

## 🧩 نحوه کار (برای کنجکاوها)

```
فرستنده ──✉──▶ Cloudflare MX (Email Routing)
                    │  قانون Catch-all
                    ▼
              Worker.email()  ──▶ پارس MIME با postal-mime
                    │
                    ▼
        Workers KV:  mail:آدرس:زمان:شناسه  (+ پیوست‌ها در کلیدهای جدا)
                    ▲
                    │ خواندن با رمز صندوق
              پنل وب (همین ورکر، صفحه /inbox)
```

همه‌چیز در همان یک فایل `worker.js` است: روتر، API، هندلر ایمیل، و رابط کاربری که خود ورکر سرو می‌کند — بدون هیچ وابستگی خارجی دیگری.
